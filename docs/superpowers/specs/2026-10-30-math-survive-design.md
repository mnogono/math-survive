# Math Survive — дизайн

Дата: 2026-10-30. Статус: черновик на согласовании.

## Зачем

Настольная игра-компаньон, которая живёт на рабочем столе Windows поверх работы. Развлекает и учит:
игрок решает задачи по математике (квиз с вариантами ответа), за верные ответы получает патроны, а
периодически на его персонажа идёт орда зомби, и он смотрит, хватило ли решённых задач, чтобы
отбиться.

Играют школьники, студенты, просто интересующиеся и сам автор — прямо во время работы за компьютером.
Главное требование: игра не мешает работать. Пока игрок не хочет решать задачу, игра стоит и ничего не
требует.

## Цели

- Задачи по математике выше арифметики: дроби, степени, корни, производные, интегралы, греческие буквы,
  специальные символы — формулы отображаются как в учебнике (LaTeX-качество).
- Квиз с вариантами ответа: игрок ничего не вводит с клавиатуры, только кликает.
- Сложность растёт внутри выбранного раздела.
- Игровой цикл «задачи → орда-кино → задачи», орды со временем больше.
- Статистика: решённые задачи, время на решение, убитые зомби и т.п.
- Устройство, позволяющее позже добавить другие предметы (история, иностранный язык) без переделки
  игры — только новые пакеты вопросов.

## Не цели (сейчас)

- Нормальные 3D-модели и анимации — первые этапы на примитивах. Модели и анимации позже с
  Mixamo (https://www.mixamo.com/).
- Ввод ответа с клавиатуры.
- Предметы кроме математики (только задел в формате).
- Несколько мониторов, macOS/Linux, сетевые функции.

## Анти-цели (провал, даже если «работает»)

- Игра крадёт фокус клавиатуры у рабочих приложений или сама всплывает окнами поверх работы.
- Прозрачное окно игры перехватывает клики мимо её элементов (по рабочему столу, по окнам, по панели
  задач).
- Игра заметно нагружает процессор, пока стоит (ждёт клика по «!»).
- Формулы нечитаемы или выглядят «самодельно».

## Как выглядит (решено с пользователем, макет «вариант A»)

- Игра — прозрачное окно без рамки поверх всех окон на весь основной монитор. Видны только её
  элементы, клики мимо них проходят насквозь к окнам под ней.
- Персонаж (3D, с оружием в руках) стоит слева внизу, на нижнем краю рабочей области — над панелью
  задач Windows. Пока — примитив (капсула/кубик с «ружьём»).
- Позади персонажа (левее) — **дверь**. Клик по двери сохраняет прогресс и закрывает игру.
- Над персонажем — **облачко «!»** (мигает), когда есть задача.
- Клик по «!» раскрывает **квиз-облачко** прямо над персонажем (как реплика комикса): условие задачи
  (текст + формула), четыре варианта ответа (формулы) сеткой 2×2, внизу кнопка **«⏸ Пауза»**.
  Остальной экран квиз не перекрывает.
- Текстовые задачи допустимы (решение пользователя): длинное условие и варианты-слова или смесь
  текста и формул. Квиз-облачко подстраивает размер под содержимое: короткая задача — компактное
  облачко с сеткой 2×2; длинная — облачко шире/выше, варианты столбиком. Облачко остаётся над
  персонажем и не выходит за край экрана.
- **Патроны не показываются** нигде во время игры (решение пользователя: интрига). Показываются только
  в статистике в конце.
- Зомби приходят из-за правого края экрана вдоль нижнего края рабочей области.

## Игровой цикл (решено с пользователем)

### Режим задачи

- Всегда есть следующая задача: при запуске и после каждого ответа над персонажем мигает «!».
- Пока «!» не нажат, **игра стоит целиком**: игровое время не идёт, зомби не двигаются.
- **Игровое время течёт только пока квиз раскрыт.**
- Верный ответ: + патроны, + точность. Неверный: − точность (дебаф).
- **Пауза** — внутри раскрытой задачи. Убирает задачу на 10 минут (настраивается, реальное время).
  Пауза **разовая**: после использования снова доступна только после следующего верного ответа.

### Режим орды («кино»)

- Орда начинается, когда накопилось **30 минут игрового времени** (настраивается), то есть 30 минут
  с раскрытыми задачами, а не по часам.
- Во время орды задачи не поступают. Игрок ничего не делает — смотрит: персонаж стреляет сам (не
  управляется человеком), тратит патроны, попадает с текущей вероятностью (точностью).
- Каждая следующая орда больше предыдущей.
- Патроны кончились и зомби дошёл до персонажа — **game over**, показывается статистика.

### Меню

- Двухуровневое: **область знаний → раздел**. Сейчас одна область — «Математика».
- Разделы математики первой версии: **«Дроби»**, **«Производные»**, **«Интегралы»** (вместе
  покрывают весь набор формул: дроби, степени, ∫, греческие буквы). Позже — степени и корни,
  уравнения, тригонометрия, последовательности и суммы, пределы.

## Отображение формул (решение)

Офисные пакеты и Notepad не используются: Notepad не рисует формулы, Office тяжёлый, крадёт фокус и
неуправляем из игры. Всё рисуется внутри Godot.

Выбран путь **«LaTeX → SVG заранее»**:

- Формулы условия и вариантов ответа заранее отрисованы в SVG (MathJax, вывод путями без внешних
  шрифтов — `fontCache: 'none'`, чтобы SVG был самодостаточным).
- Игра загружает SVG во время работы (`Image.LoadSvgFromString` с масштабом под нужный размер, чтобы
  формулы были чёткими) и показывает как текстуру.
- Текст условия на русском («Найдите производную:») — обычный текст Godot, не SVG.
- **Риск, проверить первым делом (этап 1):** что растеризатор SVG в Godot (ThorVG) корректно рисует
  вывод MathJax (дроби, ∫, корни, индексы). Если нет — запасные варианты по порядку: другие
  настройки вывода MathJax; растеризация в PNG генератором; свой мини-рендерер в Godot.

## Пакеты вопросов (решение исполнителя)

Игра не знает, что такое математика: она загружает пакет вопросов, показывает вопрос и проверяет
выбранный вариант. Формат один для всех предметов.

Предлагаемая структура:

```
packs/
  math/                     # область
    area.json               # { "id": "math", "title": "Математика" }
    fractions/              # раздел
      section.json          # { "id": "fractions", "title": "Дроби", "levels": 10 }
      questions.json
      svg/<question-id>-q.svg, <question-id>-a0.svg ... -a3.svg
```

Вопрос в `questions.json`:

```json
{
  "id": "fractions-L3-0042",
  "level": 3,
  "prompt": "Вычислите:",
  "prompt_svg": "svg/fractions-L3-0042-q.svg",
  "options": [
    { "svg": "svg/fractions-L3-0042-a0.svg" },
    { "svg": "svg/fractions-L3-0042-a1.svg" },
    { "svg": "svg/fractions-L3-0042-a2.svg" },
    { "svg": "svg/fractions-L3-0042-a3.svg" }
  ],
  "correct": 2
}
```

Любое из `prompt_svg` / `svg` может быть заменено на `text` (для текстовых предметов). Порядок
вариантов на экране перемешивается игрой. Точную схему (поля, необязательные части) исполнитель может
уточнить, сохранив принцип «одна схема для всех предметов».

## Источник задач (решение пользователя: сначала готовые квизы)

Пользователь предпочитает **готовые квизы**: в них составители подбирают «приятные» ответы (целые
числа, простые дроби), чего случайная генерация сама по себе не даёт.

Поэтому в репозитории — инструменты подготовки пакетов (`tools/`, Python 3), не часть игры:

1. **Импортёр готовых квизов** (основной источник):
   - читает открытый набор вопросов с вариантами ответа;
   - отбирает вопросы по разделам («Дроби», «Производные», «Интегралы») — по ключевым словам/LaTeX,
     с ручной проверкой спорных; текстовые задачи подходят наравне с формульными;
   - назначает уровень сложности (из поля сложности набора, если есть; иначе по «ступени» набора:
     элементарная → школьная → вузовская);
   - если вопрос не на русском — переводит текст условия (формулы не трогает), перевод проверяется;
   - выделяет формулы условия и вариантов и рисует их в SVG.
   Кандидаты (лицензию каждого проверить по карточке набора до использования):
   - **ruMMLU из MERA** (`ai-forever/MERA`, `MERA-evaluation/MERA`, карточка — MIT) — русский перевод
     MMLU, есть математические предметы, 4 варианта. Первый кандидат.
   - **MMLU** (`cais/mmlu`: elementary_mathematics, high_school_mathematics, college_mathematics) —
     4 варианта, на английском, обычно MIT.
   - **TAL-SCQ5K** (`math-eval/TAL-SCQ5K`) — 5000 вопросов с вариантами, LaTeX, сложность 0–4,
     англ./кит.; лицензия в карточке неоднозначна (MIT в одной версии).
   - Квизы OpenStax Calculus (CC BY-NC, только многомерный анализ) — запасной.
   Банки ЕГЭ/ОГЭ не использовать (авторские права).
2. **Генератор** (дополнение там, где готовых вопросов мало — ожидаемо производные и интегралы):
   - Python 3 + SymPy, шаблоны по разделам и уровням;
   - «приятные» ответы — задача строится от ответа: сначала выбирается красивый ответ, потом под него
     подбирается условие;
   - неверные варианты — из типичных ошибок (потерянный знак, забытый множитель/степень, ошибка в
     правиле, неверные пределы интеграла), не совпадают между собой и с верным (проверка SymPy).
- LaTeX → SVG в обоих инструментах: MathJax (Node.js, пакет `mathjax-full`).
- Объём для старта: по 10 уровней на раздел, 30–50 вопросов на уровень (сколько наберётся из
  готовых, остальное — генератор).

## Механика (числа — решения исполнителя, все в `settings.ini`)

| Параметр | Значение по умолчанию |
|---|---|
| Интервал орды (игровые минуты) | 30 |
| Длительность паузы (реальные минуты) | 10 |
| Патроны на старте | 30 |
| Патроны за верный ответ | +3 |
| Точность на старте | 100% |
| Точность за верный ответ | +5% (не выше 100%) |
| Точность за неверный ответ | −10% (не ниже 20%) |
| Зомби в орде N | 5 + 3·(N−1) |
| Попаданий на зомби | 1 |
| Дальность начала стрельбы | треть ширины экрана от персонажа |
| Повышение уровня | 3 верных подряд |
| Понижение уровня | 2 неверных подряд (не ниже 1) |

Скорость зомби, интервал их выхода и темп стрельбы — подобрать так, чтобы орда шла 1–2 минуты.

## Решения исполнителя по поведению (пользователь может поправить)

- После ответа квиз показывает результат ~1,5 с (верный вариант подсвечивается зелёным, выбранный
  неверный — красным), затем закрывается, и сразу снова мигает «!» со следующей задачей.
- Квиз можно свернуть без ответа повторным кликом по облачку — время снова стоит; задача остаётся той же.
- Во время паузы «!» не показывается, игровое время стоит; через 10 минут «!» возвращается.
- Если игровое время дошло до порога орды при раскрытом квизе — квиз закрывается, текущий вопрос не
  засчитывается и будет показан после орды, начинается орда.
- Конец орды без поражения: короткая сводка («Орда 3 отбита, убито 11») на несколько секунд, затем
  снова режим задачи.
- Вопросы в пределах уровня выбираются случайно без повторов, пока уровень не исчерпан.
- Сменить раздел посреди игры: клик по персонажу открывает маленькое меню («Сменить раздел»,
  «Статистика»). Меню «область → раздел» показывается при первом запуске и после game over.
- После game over: боевое состояние (патроны, точность, номер орды, игровое время) сбрасывается,
  уровни сложности по разделам и общая статистика сохраняются.
- Сохранение в `save.json` после каждого ответа, конца орды и при выходе через дверь (на случай сбоя).

## Статистика

Показывается после game over (и по запросу через меню персонажа):

- задачи: верно / неверно, по разделам;
- среднее время на задачу (время с раскрытым квизом);
- максимальный достигнутый уровень по разделам;
- убито зомби, отбито орд;
- патронов потрачено и осталось.

Хранится и за текущий забег, и за всё время.

## Файлы

- `settings.ini` — формат INI (читается `ConfigFile` Godot). Должен легко находиться пользователем:
  рядом с исполняемым файлом в собранной игре; в редакторе — на усмотрение исполнителя. При отсутствии
  создаётся со значениями по умолчанию.
- `save.json` — прогресс: выбранная область/раздел, уровни и счётчики подряд по разделам, использованные
  вопросы, боевое состояние, игровое время до орды, состояние паузы, статистика.

## Технические заметки для исполнителя

- Прозрачное окно поверх всех: borderless, transparent, always on top, per-pixel transparency; окно —
  на рабочую область основного монитора (`DisplayServer.ScreenGetUsableRect`).
- Клики насквозь: `DisplayServer.WindowSetMousePassthrough` с многоугольником(ами) вокруг видимых
  интерактивных элементов (дверь, персонаж, «!», квиз), обновлять при изменении.
- Управление в игре — только мышь, клавиатура игре не нужна (решение пользователя). Поэтому окно игры
  не должно забирать фокус клавиатуры у рабочих окон. Цель — окно, которое не активируется при клике
  (Win32 `WS_EX_NOACTIVATE` через P/Invoke или аналог), при этом клики мыши Godot получает. Проверить
  ранним прототипом на этапе 0. Запасной вариант (решение исполнителя): если без активации Godot не
  получает клики — после каждого клика по элементам игры возвращать фокус окну, которое было активно до
  клика. Пример, что задача выполнима: плагин Popup Review для Obsidian (всплывающее окно поверх всех
  без захвата фокуса).
- Окно игры не должно пропадать/уходить под другие окна при клике в рабочие приложения (известная
  проблема похожих игр, напр. Rusty's Retirement) — проверить на этапе 0.
- Пока игра стоит — минимальная нагрузка (low processor mode или аналог).
- 3D-персонаж и зомби: 3D-сцена с ортографической камерой в прозрачном окне (или SubViewport) — на
  усмотрение исполнителя.
- Логику (патроны, точность, игровое время, орда, уровни, выбор вопросов, статистика, сохранение)
  держать в обычных C#-классах без зависимости от узлов Godot и покрыть юнит-тестами.

## Этапы

0. **Каркас.** Проект Godot C#, прозрачное окно поверх всех на рабочую область, клики насквозь,
   персонаж-примитив на нижнем краю, дверь (выход), облачко «!».
1. **Квиз.** Формат пакета, загрузка SVG (сначала проверка риска ThorVG/MathJax), квиз-облачко,
   ответ, обратная связь, пауза. Тестовый пакет — несколько вопросов, SVG сделаны вручную через MathJax.
2. **Логика боя.** Игровое время, скрытые патроны, точность, порог орды, режим «кино», зомби-примитивы,
   автострельба с вероятностью попадания, game over, экран статистики.
3. **Пакеты задач.** Импортёр готовых квизов (отбор по разделам, уровни, перевод, SVG) для разделов
   «Дроби», «Производные», «Интегралы»; генератор (SymPy, «ответ сначала») — добить недостающие уровни.
4. **Меню, сохранение, настройки.** Меню «область → раздел», меню персонажа, `save.json`,
   `settings.ini`.
5. **Графика и звук.** Модели и анимации с Mixamo (персонаж с оружием, зомби: ходьба, атака, смерть,
   стрельба), звук. Источники ассетов (лицензии сверить на странице пакета перед загрузкой):
   - **Mixamo** (бесплатно с аккаунтом Adobe; сервис в режиме поддержки) — персонаж-стрелок и зомби,
     анимации (стойка/стрельба из винтовки, `Zombie pack`: ходьба, атака, смерть). Исходные FBX не
     раздавать — в публичный репозиторий не класть.
   - **Kenney** (CC0, можно в репозиторий): Blaster Kit — оружие; Animated Characters 3 — скины
     «зомби»/«выживший» (idle, jump, run) как запасной/упрощённый вариант.
   - **Quaternius** (CC0, можно в репозиторий): Ultimate Animated Character Pack, Toon Shooter Game
     Kit (персонажи, враги, оружие), Universal Animation Library (анимации под ретаргет) — запасной
     вариант без ограничений Mixamo.
   - Оружие крепится к кости руки персонажа (`BoneAttachment3D`).
