# Math Survive

Настольная игра-оверлей для Windows: персонаж решает математические задачи, получает патроны и автоматически отбивается от орд зомби. Окно прозрачное, без рамки, поверх рабочего стола; клики вне интерактивных зон проходят насквозь.

## Стек и требования

- Godot **4.7.2 .NET (Mono)**, рендерер **GL Compatibility**.
- **.NET 8**, C# с включённым nullable; Core и тесты используют C# 12.
- **Node.js + npm** нужны только для генерации SVG из TeX.
- Запуск и экспорт рассчитаны на Windows; оверлей использует Win32 API.

Пути к Godot по умолчанию заданы в `start.cmd`, `build.cmd` и `nuget.config`. Для команд запуска и сборки их можно переопределить переменными `GODOT` и `GODOT_CON` соответственно.

## Структура

- `scripts/` — Godot-адаптер: сцены, отображение, ввод, Win32 и анимации. Namespace: `MathSurvive.Game`.
- `scenes/Main.tscn` — главная сцена; `Main.cs` связывает UI и игровую сессию.
- `core/MathSurvive.Core/` — чистая C#-логика без зависимости от Godot. Namespace: `MathSurvive.Core`.
- `tests/MathSurvive.Core.Tests/` — xUnit-тесты Core, включая проверку собранного пакета вопросов.
- `packs-src/` — исходники вопросов с TeX.
- `packs/` — готовые JSON и SVG, которые читает игра.
- `tools/tex2svg/` — генератор `prompt_tex`/`tex` → SVG через MathJax.
- `assets/` — игровые ресурсы.
- `build/` — экспортированная игра и копия пакетов; игнорируется Git.

Каталоги `core`, `tests`, `tools`, `packs-src` и `packs` содержат `.gdignore`: не добавляйте туда Godot-ресурсы, которые должны импортироваться редактором. Пакеты в собранную игру копирует `build.cmd`, а не экспортёр Godot.

## Команды

Выполнять из корня репозитория в Windows `cmd`:

```cmd
dotnet build MathSurvive.sln -nologo -v:minimal
dotnet test tests\MathSurvive.Core.Tests -nologo -v:minimal
start.cmd
build.cmd
build.cmd notest
```

- `start.cmd` собирает solution и запускает проект в Godot без редактора.
- `build.cmd` собирает solution, запускает тесты, экспортирует `build\MathSurvive.exe` и копирует `packs` рядом с exe. `notest` пропускает только тесты.
- `MathSurvive.sln` содержит Game и Core, но **не тестовый проект**: тесты запускайте отдельной командой выше.
- Не очищайте `build` целиком: рядом с программой могут лежать пользовательские `settings.ini` и `save.json`.

Отладочные аргументы передаются после `--`:

```cmd
start.cmd -- --open-quiz --question=test-L1-01
start.cmd -- --horde-now --ammo=30
start.cmd -- --open-quiz --quit-after=3 --shot=artifacts\quiz.png
```

Доступны `--open-quiz`, `--question=<id>`, `--horde-now`, `--ammo=<n>`, `--quit-after=<секунды>` и `--shot=<png>`. Парсинг находится в `scripts/DebugArgs.cs`, снимок и завершение — в `scripts/DebugCapture.cs`.

## Архитектурные правила

- Сохраняйте границу: игровые правила и вычисления — в `MathSurvive.Core`, типы и вызовы Godot — в `scripts`. Core должен оставаться тестируемым обычным `dotnet test`.
- `GameSession` (`core/MathSurvive.Core/Session/GameSession.cs`) — машина состояний: `Idle`, `QuizOpen`, `Feedback`, `Paused`, `Horde`, `HordeSummary`, `GameOver`. Изменения режима и побочные эффекты правил проводите через неё, а не через отдельные UI-классы.
- `Main` — composition root: создаёт сессию, загружает пакет, подписывает представления на события. `HordeDirector` управляет визуальной ордой, но выстрелы и завершение боя выполняет через `GameSession`.
- Игровой таймер орды идёт только в `QuizOpen`; пауза использует `DateTime.UtcNow`. Кадровая дельта ограничивается `GameConfig.MaxFrameDeltaSec`.
- Настройки баланса собраны в неизменяемой записи `GameConfig`; для вариантов конфигурации используйте `with`.
- Ответы хранятся в исходном порядке, а `QuizView.Order` задаёт перемешанный порядок показа. Не смешивайте исходный индекс варианта и display-индекс.
- `PacksRoot.Path`: в редакторе — `res://packs`, в собранной игре — `packs` рядом с exe. Сохраняйте обе схемы при изменении загрузки.

### Оверлей и координаты

- Физические пиксели окна, логические пиксели UI и мировые координаты 3D — разные системы. UI масштабируется через `UiScale`; преобразования для сцены выполняет `Stage`.
- Начало экранных координат — левый верхний угол, мировых — левый нижний. В `Stage` 1 мировая единица = 100 логических px.
- `DesktopOverlay` регистрирует интерактивные зоны в физических px и переключает `WS_EX_TRANSPARENT` из фонового потока. Узлы Godot читайте только в главном потоке; фоновому потоку передавайте готовый снимок данных.
- Порядок настройки флагов окна и Win32-стилей существенен: Win32-стили применяются после настройки окна Godot.
- Для изменений UI проверяйте не только компиляцию, но и запуск соответствующего режима; для проверки кадра используйте `--shot` и `--quit-after`.

## Пакеты вопросов

Исходник текущего раздела — `packs-src/math/test/questions.src.json`. Не правьте вручную производные `packs/math/test/questions.json` и `packs/math/test/svg/*.svg`: генератор перезаписывает их и удаляет старые SVG в выходном каталоге.

После изменения исходника:

```cmd
cd tools\tex2svg
npm ci
node build-pack.mjs ..\..\packs-src\math\test\questions.src.json ..\..\packs\math\test
cd ..\..
dotnet test tests\MathSurvive.Core.Tests -nologo -v:minimal
```

Формат и ограничения:

- У вопроса обязательны уникальный `id`, положительный `level`, `prompt` и/или `prompt_tex`, ровно **4** варианта и `correct`.
- `correct` — **zero-based** индекс правильного варианта в исходном JSON; в игре варианты перемешиваются.
- Вариант содержит `text` или `tex`. В сгенерированном пакете текст остаётся `text`, TeX заменяется путём `svg`.
- `section.json` задаёт `id`, `title` и число уровней `levels`.
- `BuiltPackTests` проверяет текущий пакет, наличие SVG и конкретное число вопросов. При изменении состава пакета обновите это ожидание.

## Стиль и тесты

- Следуйте существующему стилю: file-scoped namespaces, 4 пробела, выражения-члены для простых методов, записи для неизменяемых данных.
- Сохраняйте русские пользовательские строки и стиль существующих пояснений; не добавляйте очевидные комментарии.
- Для изменений Core добавляйте xUnit-тесты рядом с тестами соответствующего класса. Используйте seeded `Random`, когда проверяете случайное поведение.
- Для новых C#-скриптов Godot сохраняйте создаваемые редактором `.cs.uid` вместе со скриптом.
- Не редактируйте генерируемые каталоги `.godot`, `bin`, `obj`, `node_modules` и содержимое `build` как исходный код.

## Проверка перед завершением

1. `dotnet build MathSurvive.sln -nologo -v:minimal`.
2. `dotnet test tests\MathSurvive.Core.Tests -nologo -v:minimal`.
3. При изменении пакета — перегенерировать его и прогнать `BuiltPackTests` в составе общего тестового запуска.
4. При изменении Godot/UI/Win32 — запустить реальный сценарий через `start.cmd` с подходящими отладочными аргументами; проверить кликабельные зоны и прозрачность вручную, если они затронуты.
5. Полный экспорт выполнять через `build.cmd` после успешной сборки и тестов; не заменяйте его удалением или ручной сборкой каталога `build`.
