# Math Survive

Настольная игра-оверлей для Windows: персонаж решает математические задачи, получает патроны и автоматически отбивается от орд зомби. Окно прозрачное, без рамки, поверх рабочего стола; клики вне интерактивных зон проходят насквозь. В нижней полосе экрана — комната: стена с табличками четырёх разделов (арифметика, алгебра, геометрия, математический анализ) и круглой монетой-переключателем у каждой. По клику по стене персонаж стреляет в эту точку (патроны не тратятся): попадание в монету переворачивает её и включает или выключает раздел, остальные выстрелы оставляют следы на стене и табличках. Каждый новый вопрос берётся из случайного включённого раздела. Дверь слева — выход из игры.

## Стек и требования

- Godot **4.7.2 .NET (Mono)**, рендерер **GL Compatibility**.
- **.NET 10**, C# с включённым nullable; Core и тесты используют C# 12.
- **Node.js + npm** нужны только для генерации SVG из TeX.
- Запуск и экспорт рассчитаны на Windows; оверлей использует Win32 API.

Пути к Godot по умолчанию заданы в `start.cmd`, `build.cmd` и `nuget.config`. Для команд запуска и сборки их можно переопределить переменными `GODOT` и `GODOT_CON` соответственно.

## Структура

- `scripts/` — Godot-адаптер: сцены, отображение, ввод, Win32 и анимации. Namespace: `MathSurvive.Game`.
- `scenes/Main.tscn` — главная сцена; `Main.cs` связывает UI, комнату (`RoomView`: таблички `RoomIconView`, монеты `CoinView`), дверь (`DoorView`) и игровую сессию.
- `core/MathSurvive.Core/` — чистая C#-логика без зависимости от Godot. Namespace: `MathSurvive.Core`.
- `tests/MathSurvive.Core.Tests/` — xUnit-тесты Core, включая проверку собранного пакета вопросов.
- `packs-src/` — исходники вопросов с TeX.
- `packs/` — готовые JSON и SVG, которые читает игра.
- `tools/tex2svg/` — генератор `prompt_tex`/`tex` → SVG через MathJax.
- `assets/` — игровые ресурсы.
- `build/` — экспортированная игра и копия пакетов; игнорируется Git.

Каталоги `core`, `tests`, `tools`, `packs-src` и `packs` содержат `.gdignore`: не добавляйте туда Godot-ресурсы, которые должны импортироваться редактором. Пакеты в собранную игру копирует `build.cmd`, а не экспортёр Godot.

## Команды

Выполнять из корня репозитория в Windows `cmd`:

```cmd
dotnet build MathSurvive.sln -nologo -v:minimal
dotnet test tests\MathSurvive.Core.Tests -nologo -v:minimal
start.cmd
build.cmd
build.cmd notest
```

- `start.cmd` собирает solution и запускает проект в Godot без редактора.
- `build.cmd` собирает solution, запускает тесты, экспортирует `build\MathSurvive.exe` и копирует `packs` рядом с exe. `notest` пропускает только тесты.
- `MathSurvive.sln` содержит Game и Core, но **не тестовый проект**: тесты запускайте отдельной командой выше.
- Не очищайте `build` целиком: рядом с программой могут лежать пользовательские `settings.ini` и `save.json`.

Отладочные аргументы передаются после `--`:

```cmd
start.cmd -- --open-quiz --question=test-L1-01
start.cmd -- --horde-now --ammo=30
start.cmd -- --open-quiz --quit-after=3 --shot=artifacts\quiz.png
start.cmd -- --fire=geometry --fire=1000,1400 --quit-after=3 --shot=artifacts\room.png
```

Доступны `--open-quiz`, `--question=<id>`, `--horde-now`, `--ammo=<n>`, `--fire=<section|x,y>`, `--quit-after=<секунды>` и `--shot=<png>`. `--question` включает только раздел, которому принадлежит вопрос (для `test-*` подключается отладочный пакет `math/test`), и отключает запись `save.json`. `--fire` можно повторять: выстрелы идут по очереди с паузой 0,6 с — в монету раздела или в точку окна (физические px), как клик по стене. Парсинг находится в `scripts/DebugArgs.cs`, снимок и завершение — в `scripts/DebugCapture.cs`.

## Архитектурные правила

- Сохраняйте границу: игровые правила и вычисления — в `MathSurvive.Core`, типы и вызовы Godot — в `scripts`. Core должен оставаться тестируемым обычным `dotnet test`.
- `GameSession` (`core/MathSurvive.Core/Session/GameSession.cs`) — машина состояний: `Idle`, `QuizOpen`, `Feedback`, `Paused`, `Horde`, `HordeSummary`, `GameOver`. Изменения режима и побочные эффекты правил проводите через неё, а не через отдельные UI-классы.
- `Main` — composition root: загружает четыре пакета, создаёт `QuestionCatalog` и сессию, восстанавливает прогресс, подписывает представления на события. `HordeDirector` управляет визуальной ордой, но выстрелы и завершение боя выполняет через `GameSession`.
- Игровой таймер орды идёт только в `QuizOpen`; пауза использует `DateTime.UtcNow`. Кадровая дельта ограничивается `GameConfig.MaxFrameDeltaSec`.
- Настройки баланса собраны в неизменяемой записи `GameConfig`; для вариантов конфигурации используйте `with`.
- Ответы хранятся в исходном порядке, а `QuizView.Order` задаёт перемешанный порядок показа. Не смешивайте исходный индекс варианта и display-индекс.
- `PacksRoot.Path`: в редакторе — `res://packs`, в собранной игре — `packs` рядом с exe. Сохраняйте обе схемы при изменении загрузки.

### Разделы, сложность и сохранение

- `QuestionCatalog` (`core/MathSurvive.Core/Questions`) хранит пакеты разделов; у каждого раздела свои `DifficultyTracker` (уровень, correct/wrong streaks) и показанные ID по уровням. `GameSession.Pack`/`Difficulty` делегируют активному разделу — разделу последнего выданного вопроса.
- Вопрос выбирается строго на текущем уровне активного раздела (`QuestionPicker.NextAtLevel`) без повторов до исчерпания уровня; перехода на соседние уровни нет. Старый `QuestionPicker.Next` с fallback оставлен для совместимости.
- Разделы включаются и выключаются независимо (`EnabledSectionIds`); по умолчанию включены все четыре. Новый вопрос берётся из равновероятно выбранного включённого раздела через общий seeded `Random`. Последний включённый раздел выключить нельзя: `SetEnabled`/`ToggleSection` возвращают `false`, монета покачивается.
- `GameSession.ToggleSection` работает только в `Idle`/`QuizOpen` (`CanToggleSections`); бой, пауза, часы и статистика не меняются. Если выключен раздел неотвеченного вопроса, вопрос сбрасывается без записи ответа: открытый квиз сразу получает вопрос из включённых разделов, свёрнутый — при следующем открытии. Сворачивание и орда текущий вопрос не меняют. `EnableOnlySection` — только для отладочного `--question` до начала игры.
- Комната (`RoomView`): вся стена — одна зона клика, пока разделы можно переключать. `Main.OnRoomClicked` вызывает `PlayerView.ShootAt` (поворот к цели, вспышка, след пули; `CombatState` не трогает) и по `RoomView.CoinAt` переключает раздел через сессию; пока монета переворачивается, повторные попадания в неё игнорируются. Следы пуль на стене — 3D-диски перед стеной (за персонажем), на табличках — рисуются самой табличкой; число следов ограничено, при перезапуске они не сохраняются. Раскладку табличек и монет задаёт `RoomLayout.SectionSlots`; персонаж стоит в первой колонке и не ходит.
- Дверь (`DoorView`) — `Sprite3D` из `assets/door.png` (кадры сверху вниз: открыта, приоткрыта, закрыта; пиксель спрайта = 2 логических px, фильтр nearest, импорт без сжатия для 3D). По клику дверь открывается и после анимации сообщает `Opened`, `Main` завершает игру.
- Каталог, сессия и `ProgressSaveCodec` получают один и тот же `GameConfig`: допустимые серии — от 0 до порога минус один.
- `save.json` (`version: 2`) содержит только `enabled_section_ids`, уровни, серии и used IDs по уровням каждого раздела; текущий вопрос, следы пуль и бой не сохраняются. Файл версии 1 (`selected_section_id`) читается: прогресс разделов сохраняется, включаются все разделы. Пустой список, повтор или неизвестный раздел в `enabled_section_ids` делают файл недопустимым. Путь — `user://save.json` в редакторе и `save.json` рядом с exe в собранной игре (`ProgressSaveStore`). Сохранение после ответа, применённого переключения раздела и при выходе; запись через `save.json.tmp` в том же каталоге с заменой (`ProgressFileStore`). Отсутствующий, повреждённый или недопустимый файл даёт значения по умолчанию; неизвестные ID вопросов отбрасываются, разделы без записи начинают с уровня 1.

### Оверлей и координаты

- Физические пиксели окна, логические пиксели UI и мировые координаты 3D — разные системы. UI масштабируется через `UiScale`; преобразования для сцены выполняет `Stage`.
- Начало экранных координат — левый верхний угол, мировых — левый нижний. В `Stage` 1 мировая единица = 100 логических px.
- `DesktopOverlay` регистрирует интерактивные зоны в физических px и переключает `WS_EX_TRANSPARENT` из фонового потока. Узлы Godot читайте только в главном потоке; фоновому потоку передавайте готовый снимок данных.
- Порядок настройки флагов окна и Win32-стилей существенен: Win32-стили применяются после настройки окна Godot.
- Для изменений UI проверяйте не только компиляцию, но и запуск соответствующего режима; для проверки кадра используйте `--shot` и `--quit-after`.

## Пакеты вопросов

Исходники разделов — `packs-src/math/<section>/questions.src.json` (`arithmetic`, `algebra`, `geometry`, `analysis` и отладочный `test`; рисунки — в `images/` рядом). Игра загружает четыре раздела; `math/test` — только для `--question=test-*` и тестов. Не правьте вручную производные `packs/math/<section>/questions.json`, `svg/*.svg` и `images/*.svg`: генератор перезаписывает их и удаляет старые SVG в выходном каталоге. Ниже команды показаны для `test`; для другого раздела замените имя.

После изменения исходника:

```cmd
cd tools\tex2svg
npm ci
node build-pack.mjs ..\..\packs-src\math\test\questions.src.json ..\..\packs\math\test
cd ..\..
dotnet test tests\MathSurvive.Core.Tests -nologo -v:minimal
```

Формат и ограничения:

- У вопроса обязательны уникальный `id`, положительный `level`, хотя бы одно из `prompt`, `prompt_tex`, `prompt_image`, ровно **4** варианта и `correct`.
- `prompt_image` — путь `images/<question-id>.svg` относительно каталога исходника; генератор кладёт рисунок по тому же пути в пакет.
- Godot не рисует `<text>` в SVG. Надписи рисунка пишите как `<text x y font-size text-anchor>TeX</text>` — генератор превращает их в контуры MathJax. Кириллица внутри TeX (и в `\text{}`) не поддерживается: генератор падает; слова и единицы измерения держите в `prompt`/`text`.
- `correct` — **zero-based** индекс правильного варианта в исходном JSON; в игре варианты перемешиваются.
- Вариант содержит `text` или `tex`. В сгенерированном пакете текст остаётся `text`, TeX заменяется путём `svg`.
- `section.json` задаёт `id`, `title` и число уровней `levels`.
- `BuiltPackTests` проверяет пакеты, наличие SVG, отсутствие `<text>` и распределение вопросов по уровням. При изменении состава пакета обновите это ожидание.

## Стиль и тесты

- Следуйте существующему стилю: file-scoped namespaces, 4 пробела, выражения-члены для простых методов, записи для неизменяемых данных.
- Сохраняйте русские пользовательские строки и стиль существующих пояснений; не добавляйте очевидные комментарии.
- Для изменений Core добавляйте xUnit-тесты рядом с тестами соответствующего класса. Используйте seeded `Random`, когда проверяете случайное поведение.
- Для новых C#-скриптов Godot сохраняйте создаваемые редактором `.cs.uid` вместе со скриптом.
- Не редактируйте генерируемые каталоги `.godot`, `bin`, `obj`, `node_modules` и содержимое `build` как исходный код.

## Проверка перед завершением

1. `dotnet build MathSurvive.sln -nologo -v:minimal`.
2. `dotnet test tests\MathSurvive.Core.Tests -nologo -v:minimal`.
3. При изменении пакета — перегенерировать его и прогнать `BuiltPackTests` в составе общего тестового запуска.
4. При изменении Godot/UI/Win32 — запустить реальный сценарий через `start.cmd` с подходящими отладочными аргументами; проверить кликабельные зоны и прозрачность вручную, если они затронуты.
5. Полный экспорт выполнять через `build.cmd` после успешной сборки и тестов; не заменяйте его удалением или ручной сборкой каталога `build`.
